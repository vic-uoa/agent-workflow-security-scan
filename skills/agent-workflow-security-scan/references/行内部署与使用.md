# 行内部署与使用

本包是面向 Dify 二次开发平台的确定性 Workflow DSL 静态扫描器。默认不调用模型、不执行 Workflow、不请求业务接口，也不会运行生成的测试输入。

## 环境

- Python 3.10 或更高版本。
- 依赖：`PyYAML>=6.0,<7`、`jsonschema>=4.20,<5`。
- Windows PowerShell、Linux shell 均可使用；命令中的路径按实际环境调整。

联网环境可安装依赖：

```powershell
python -m pip install -r .\scripts\requirements.txt
```

隔离网络应先在同操作系统、同 CPU 架构和同 Python 版本的制品机下载 wheel，再通过行内制品库或审批介质导入：

```powershell
python -m pip download -r .\scripts\requirements.txt -d .\wheelhouse
python -m pip install --no-index --find-links .\wheelhouse -r .\scripts\requirements.txt
```

wheel 与本扫描器 ZIP 都应纳入行内制品完整性校验。包内 `SHA256SUMS.txt` 可检查扫描器文件；外部 ZIP 的 SHA-256 见随包验证清单。

## 扫描

在解压后的 `agent-workflow-security-scan` 目录执行：

```powershell
python .\scripts\scan_workflow.py scan `
  --mode assessment `
  --dsl C:\path\workflow.yml `
  --output C:\path\scan-output `
  --llm disabled
```

Linux 示例：

```bash
python3 ./scripts/scan_workflow.py scan \
  --mode assessment \
  --dsl /path/workflow.yml \
  --output /path/scan-output \
  --llm disabled
```

输出目录只生成以 DSL 文件名命名的子目录，其中包含：

- `<工作流名>-安全扫描报告.html`
- `<工作流名>-输入测试簇.json`

输入测试簇始终标记为 `NOT_EXECUTED`。扫描命令退出码含义：`0` 表示门禁通过，`1` 表示静态结果触发发布门禁，`2` 表示输入、解析或扫描器错误。退出码 `1` 不代表扫描器运行失败。

## 行内二开配置

`config/internal-baseline.yml` 是操作员维护的基线。可在 `tool_registry` 中登记已审查插件、接口副作用、实际执行字段、会话/持久记忆模式和版本完整性控制。具体字段与例子见 [v0.11.0 静态扫描校准](semantic-calibration-20260908.md)。

基线必须由扫描服务侧读取，不能接受待扫描 DSL 覆盖。扫描器会丢弃 DSL 中伪造的 `_scanner_registry`。生产环境建议对基线实行代码评审、版本固定和制品签名，并在升级 Dify 或插件后重新复核契约。

## 上线前自检

```powershell
python -X utf8 -m unittest discover -s .\tests -p "test*.py"
python -X utf8 .\scripts\validate_enterprise_suite.py --output C:\path\validation-output
```

当前发布基线应通过 86 项单元测试和 29 个企业验收场景。企业验收中的危险样例出现 `FAIL` 门禁是预期结果；最终验收摘要的 `Overall` 必须是 `PASS`。

## 数据边界

报告包含 DSL 中的节点标题、变量路径和必要证据。部署时应把输入、输出、临时目录和日志放在行内批准的存储区域，并按工作流数据等级控制访问。不要将含真实业务信息的 DSL、HTML 报告或测试簇上传到公网服务。

静态扫描能确认 DSL 字段、类型、变量绑定和图路径，不能证明运行时 IAM、服务端对象授权、网络出口、插件实现、模型攻击成功、持久存储隔离或沙箱逃逸。相关未知信息会保留为待核验风险或覆盖缺口。
